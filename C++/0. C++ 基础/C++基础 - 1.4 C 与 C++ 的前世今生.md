# C 与 C++ 的前世今生

## 一句话定义
C 与 C++ 是共享同一条“贝尔实验室血统”和大部分语法、但由两个独立标准委员会分别演化、目标与语义并不互相兼容的两种编程语言；C++ 起源于 C，却不是 C 的超集，也不是 C 的升级版。

## 核心理解
- **是什么**：C 是面向系统编程的过程式语言，C++ 是在 C 基础上加入抽象机制（类、模板、异常、RAII、泛型、并发）的多范式语言，二者各自有 ISO 标准。
- **为什么需要它**：C++ 早期为了复用 C 的生态和性能模型，刻意保持与 C 的源码级接近；但要支持抽象与类型安全，又必须在若干规则上与 C 分道扬镳。
- **它解决了什么问题**：C 解决“用可移植的高级语言写操作系统与基础设施”；C++ 解决“在不牺牲性能的前提下写大型、可抽象、可复用的系统软件”。理解二者的关系，才能正确判断代码能不能混编、能不能互迁、接口该用哪种 ABI。

## 详细解释

### 设计目标的差异

- **C**：保持语言极小、可预测、贴近硬件；标准库尽量薄；不引入隐藏开销和复杂运行时。C 的“可移植汇编”定位决定了它拒绝异常、泛型、自动资源管理等机制。
- **C++**：在 C 的性能模型之上支持抽象。Stroustrup 的表述大意是“尽可能接近 C，但不比需要的更接近”。C++ 需要重载、模板、异常、构造/析构，这些机制与 C 的简单符号模型天然冲突，于是产生了名字修饰、ABI 差异等分叉。

### 语义上的分叉点

“C 是 C++ 的子集”只在 C89 的大部分范围内近似成立，且有不少例外：

| 差异点 | C 的行为 | C++ 的行为 |
| --- | --- | --- |
| `void*` 转换 | 可隐式转换为任意对象指针 | 必须显式转换 |
| 空参数列表 `int f();` | 参数未指定 | 表示无参（任意参数需 `...`） |
| 字符串字面量 | 类型 `char[]`，历史上可写 | 类型 `const char[]`，写入是 UB |
| 字符常量 `'a'` | 类型 `int`，`sizeof('a')` 通常是 4 | 类型 `char`，`sizeof('a')` 为 1 |
| 结构体标签 | 必须写 `struct S` | 可直接写 `S` |
| 关键字 | `class`、`new`、`delete`、`template`、`try` 可作标识符 | 均为保留字，同名 C 代码直接报错 |
| 隐式 `int`、隐式函数声明 | 旧代码常见 | 不允许（C23 也已移除） |
| VLA / `restrict` / `_Generic` / 复合字面量 | C99/C11 支持 | 不在标准内（VLA 仅为编译器扩展） |
| 指定初始化器 | C99 起，顺序与数组成员自由 | C++20 起支持，但要求按声明顺序、不支持数组指定 |
| 函数重载与符号名 | 无重载，符号名即函数名 | 支持重载，符号名被修饰（mangling） |
| 异常与析构 | 无 | 栈展开时会调用析构函数 |

由此可以得出结论：**C++ 不是 C 的超集**；把 C 代码直接改扩展名交给 C++ 编译器，往往需要处理 `void*`、关键字冲突、隐式转换和字符串字面量等问题。

### 标准库层面的关系

C++ 把 C 标准库**适配**后纳入：`<stdio.h>` → `<cstdio>`，名称进 `std` 命名空间；`<stdlib.h>` → `<cstdlib>`；`<string.h>` → `<cstring>`。同时 C++ 标准库还包含大量与 C 无关的设施（容器、算法、iostream、线程、`filesystem`、智能指针）。

因此：

- “C++ 标准库 = C 标准库 + STL”是错的；
- C 标准库也不是 C++ 标准库的子集，两者是“同源、经适配、各自演化”的关系；
- C++ 实现通常同时提供 `<stdio.h>` 与 `<cstdio>` 两套头文件，新代码优先用 C++ 形式。

### 二进制与互操作层面

- **C 的 ABI 在平台内稳定**，函数符号不修饰，适合做动态库、跨语言调用的边界。
- **C++ 的 ABI 依赖编译器与标准库**（`libstdc++` vs `libc++`，MSVC 另有一套），符号被修饰，跨编译器链接经常失败。这就是大量 C++ 库对外暴露 C 接口的根本原因。
- 跨语言调用必须用 `extern "C"` 声明：C++ 侧按 C 规则生成和查找符号；`extern "C"` 同时会关闭该函数的 C++ 重载。

### 名字修饰

在编译阶段，编译器按 C 和 C++ 不同的命名规则，把函数名以及重载、命名空间、类作用域等信息编码成符号，由汇编器写入目标文件；链接阶段，链接器按符号名把引用解析到定义：

生成规则：

| 对比项 | C | C++ |
| --- | --- | --- |
| 符号名 | 函数名本身，如 `add`（部分平台会加 `_` 前缀，如 `_add`） | 把语言信息编码进符号名，如 `add(int, int)` → `_Z3addii` |
| 语言特性 | 无重载、命名空间、类、模板 | 有这些特性，需要靠符号名区分 |
| 重载 | 不支持 | 支持，不同重载得到不同符号 |
| 典型链接错误 | `undefined reference to 'add'` | `undefined reference to '_Z3addii'`（解修饰后为 `add(int, int)`） |

原因是**链接器只认扁平的字符串符号**，不理解 C++ 的作用域、类和重载，编译器只能把这些信息“压”进符号名。这就是名字修饰。修饰规则属于 ABI 层面，C++ 标准不规定：GCC/Clang 在 Linux、macOS 等平台使用 Itanium ABI，MSVC 使用 MS ABI，跨 ABI 的 C++ 目标文件一般不能直接互链。

`extern "C"` 赋予函数 C 语言链接，主流 ABI 下表现为符号不修饰，因此它修饰的函数不能重载；跨语言边界依赖的正是 C 这套简单、稳定的符号规则。

> 符号的生成与解析属于完整构建流程的一环，详见 [[C++基础 - 1.5 从编译到运行]]。

## 常用用法

### 在 C++ 中声明 C 接口

作用：让 C++ 编译器按 C 的链接规则处理符号，供 C/C++ 混编使用。

```cpp
extern "C" int c_function(int);          // 单个声明
extern "C" { int a(); void b(); }        // 批量声明
```

注意：被 `extern "C"` 声明的函数不能重载。

### 双向可包含的头文件写法

作用：同一个头文件既能被 C 编译，也能被 C++ 编译。

```c
/* c_header.h */
#ifdef __cplusplus
extern "C" {
#endif

int c_function(int);

#ifdef __cplusplus
}
#endif
```

注意：头文件内部不要出现类、模板、命名空间等 C 不认识的语法。

### C 代码用 C++ 编译器编译

作用：渐进迁移、复用 C++ 工具链。

```bash
g++ -x c++ legacy.c -o legacy    # 按 C++ 规则编译 C 源码
```

注意：会触发 C/C++ 规则差异（`void*`、关键字、字符串字面量等），适合小规模代码或已做兼容处理的代码。

### C++ 代码调用 C 库

作用：复用成熟的 C 库（zlib、libpng、SQLite 等）。

```bash
g++ main.cpp -lcjson -o app      # 直接链接 C 库，接口需用 extern "C" 声明
```

注意：C 库头文件若未做 `__cplusplus` 保护，需要在 C++ 侧自行包一层 `extern "C"`。

### 与相近概念对比

- **C 语言 vs C++ 语言**：独立标准，C++ 起源于 C 但语义分叉。
- **C 标准库 vs C++ 标准库**：C++ 库包含 C 库的适配版本，另有大套 C++ 专属设施。
- **GCC vs libstdc++**：前者是编译器套件，后者是可替换的标准库实现；同一编译器可搭配不同标准库。

## 常见误区
- 认为“C++ 是 C 的超集”，于是把 C 代码原样当 C++ 编译；实际会撞上大量规则差异。
- 认为“C++ 只是 C 加了类”；真正的差异在对象生命周期、RAII、异常、模板和值类别。
- 认为“C 的新特性会自动进入 C++”；两个标准独立演化，C23 的不少特性 C++ 并没有对应物。
- 认为“同名特性语义相同”；`auto`、`constexpr`、`static_assert`、`inline` 在两种语言里的规则并不一致。
- 认为“C++ 二进制到处能链接”；C++ ABI 依赖编译器与标准库，跨工具链常出问题。

## 应用场景
- **适合用在**：判断遗留 C 代码能否迁移到 C++、设计跨语言接口、选择用 C 还是 C++ 编写基础库、理解编译器与标准库生态。
- **不适合用在**：把二者当作同一门语言混写；在需要稳定 ABI 的边界直接暴露 C++ 类型；用 C 的思维（手动内存管理、指针 + 长度）写 C++ 业务代码。
