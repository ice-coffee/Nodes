# C++ 项目从编译到运行

## 一句话定义
C++ 项目从编译到运行，是“预处理 → 编译 → 汇编 → 链接 → 加载 → 运行 → 退出”的流水线：每个源文件独立编译成目标文件，链接器按符号把目标文件和库拼成可执行文件，加载器建立进程映像后由运行库调用 `main`。

## 核心理解
- **是什么**：把人类可读的 C++ 源码逐步翻译成操作系统可以加载执行的映像，并在运行时由启动代码、运行库和操作系统共同完成初始化与收尾。
- **为什么需要它**：C++ 采用分离编译模型，一个项目由多个翻译单元和库组成，必须通过符号和链接把彼此独立的产物组合起来；同时把翻译、优化、组合、加载拆成不同阶段，工具职责清晰、支持增量构建。
- **它解决了什么问题**：让源码可以分文件、分库、分团队开发，最终得到一个能加载到内存并正确执行的程序；也让同一份目标文件可以被静态链接或动态加载复用。

## 详细解释

### 整体流程

```text
main.cpp / util.cpp / *.h
        │
        │  ① 预处理 cpp
        ▼
main.ii / util.ii
        │
        │  ② 编译 cc1plus（前端 → IR → 优化 → 汇编）
        ▼
main.s / util.s
        │
        │  ③ 汇编 as
        ▼
main.o / util.o（符号表 + 重定位 + 节）
        │
        │  ④ 链接 collect2/ld（符号解析、重定位、合并节、加入启动代码和库）
        ▼
app（ELF / Mach-O / PE）
        │
        │  ⑤ 加载 exec + 动态链接器
        ▼
进程映像（代码段、数据段、堆、栈）
        │
        │  ⑥ 运行 _start → __libc_start_main → main
        ▼
main 返回 → exit → 全局析构 → _exit
```

| 阶段 | 工具 | 输入 | 输出 | 典型错误 |
| --- | --- | --- | --- | --- |
| 预处理 | `cpp` | `.cpp` + 头文件 | `.ii` | 找不到头文件、宏/条件编译错误 |
| 编译 | `cc1plus` | `.ii` | `.s` | 语法、类型、模板、访问控制错误 |
| 汇编 | `as` | `.s` | `.o` | 汇编语法错误、非法指令 |
| 链接 | `collect2` / `ld` | `.o` + `.a` / `.so` | 可执行文件或库 | `undefined reference`、`multiple definition` |
| 加载 | 内核 + `ld.so` / `dyld` | 可执行文件 + 动态库 | 进程映像 | 找不到 `.so`、符号版本不匹配 |
| 运行 | 运行库 + 程序 | 进程映像 | 程序行为 | 崩溃、未定义行为、资源泄漏 |

### 预处理

输入 `.cpp`，输出 `.ii`（C 语言是 `.i`）。主要工作是**纯文本处理**：

- 展开 `#include`，把头文件内容原样拼入
- 展开宏、处理 `#ifdef` / `#if` 条件编译
- 删除注释、处理 `#line`、保留 `#pragma`

这一阶段还没有类型检查，所以头文件缺失、宏写错、`#if` 不配对都会在这里暴露。

### 编译

输入预处理后的源码，输出汇编 `.s`。这是最重的一步，内部包括：

1. 词法与语法分析，构建 AST
2. 语义分析：类型检查、名字查找、重载决议、模板实例化、`constexpr` 求值
3. 生成中间表示（GCC 用 GIMPLE，Clang 用 LLVM IR）
4. 优化：内联、常量折叠、循环优化、向量化、寄存器分配等
5. 代码生成：目标平台汇编、调用约定、栈帧、异常表

C++ 特有的工作也集中在这里：模板实例化、虚表布局、RTTI、异常展开信息（`.eh_frame`）、全局对象初始化函数的生成。

### 汇编

输入 `.s`，输出目标文件 `.o`（Windows 为 `.obj`）。目标文件里除了机器码，还有：

- **节**：`.text` 代码、`.rodata` 只读数据、`.data` 已初始化数据、`.bss` 零初始化数据、`.init_array` 构造函数表、`.eh_frame` 展开信息
- **符号表**：`T` 已定义、`U` 未定义引用、`W` 弱符号、局部符号
- **重定位表**：记录“这个位置需要填某个符号的地址”
- **调试信息**（`-g`）：`.debug_*` 系列，与符号表是两套东西

### 链接

输入多个 `.o`、静态库 `.a`、动态库 `.so`，输出可执行文件或库。主要工作：

1. **符号解析**：把 `U` 和其他目标文件/库里的 `T` 对上，处理 weak/strong 冲突
2. **静态库按需抽取**：`.a` 中只拉入被引用的成员；链接顺序从左到右，`-lfoo` 要放在使用它的目标文件之后
3. **重定位**：填入绝对地址或相对偏移
4. **合并与布局**：拼接代码段、数据段，按链接脚本决定地址
5. **加入运行支撑**：启动文件 `crt1.o`、`crti.o`、`crtbegin.o`、`crtend.o`、`crtn.o`，以及 `libc`、`libstdc++`、`libgcc`
6. **生成动态链接信息**：`.dynamic`、`.dynsym`、PLT/GOT、`NEEDED` 依赖、`RPATH`
7. **PIE/ASLR**：现代发行版默认生成 PIE 可执行文件

注意：`undefined reference` 是**链接错误**，不是编译错误。编译阶段只要看到声明就能通过。

### 加载

执行 `./app` 时：

1. shell 调用 `execve`
2. 内核读取可执行文件头，映射代码段/数据段，建立栈（`argv`、`envp`、`auxv`）
3. 发现动态链接器信息，先加载 `ld-linux...`（macOS 是 `dyld`）
4. 动态链接器加载 `NEEDED` 依赖，完成动态重定位
5. 执行 `.init_array` 中的初始化函数
6. 跳转到入口 `_start`

常见加载错误：找不到动态库、符号版本不匹配、架构不匹配、GLIBC 版本过低。

### 运行

```text
_start（crt1.o）
  └─ __libc_start_main
       ├─ C++ 全局/静态对象动态初始化（.init_array）
       ├─ 调用 main(argc, argv)
       └─ main 返回后进入 exit(...)
```

运行期还涉及：

- **全局/静态对象构造**：在 `main` 之前执行；同一翻译单元内按声明顺序，跨翻译单元顺序未定义（静态初始化顺序问题）
- **函数内静态变量**：首次执行时初始化，C++11 起线程安全（guard variable）
- **异常**：沿 `.eh_frame` 展开栈，调用析构函数，依赖 `libgcc_s` / `libunwind`
- **虚函数与 RTTI**：vtable、`type_info` 位于只读或重定位节
- **内存**：`operator new` → `malloc` → `brk` / `mmap`
- **惰性绑定**：动态符号默认首次调用时才解析（PLT/GOT），可用 `LD_BIND_NOW=1` 改为立即绑定

### 退出

`main` 返回或调用 `exit()` 后：

1. 执行 `atexit` / `__cxa_atexit` 注册的函数
2. 调用全局/静态对象析构函数（逆构造顺序，跨翻译单元顺序同样未定义）
3. flush `stdout` 等缓冲区
4. 调用 `_exit`，内核回收资源

`std::quick_exit`、`std::abort`、`_Exit` 会跳过部分清理。
