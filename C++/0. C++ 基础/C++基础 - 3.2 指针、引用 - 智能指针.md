### 1. 简介
智能指针可以在适当时机自动释放分配的内存。也就是说，使用智能指针可以很好地避免“忘记释放内存而导致内存泄漏”问题出现。

* shared_ptr：共享
* unique_ptr：独占
* weak_ptr：弱指针

**`智能指针头文件`**：
```c++
// 头文件
#include <memory>
// 命名空间
using namespace std;
```

### 2. shared_ptr

[shared_ptr智能指针](http://c.biancheng.net/view/7898.html)

#### 2.1 初始化

**`定义`**：
```c++
std::shared_ptr<int> p1;
```

**`初始化`**：
```c++
// 空指针
std::shared_ptr<int> p2(nullptr);
// 正确初始化方式
std::shared_ptr<int> p3(new int(10));
// 错误初始化方式
std::shared_ptr<int> p3 = new int(10); 
```

`C++11` 标准中还提供了 `std::make_shared<T>` 模板函数，其可以用于初始化 `shared_ptr` 智能指针
```c++
std::shared_ptr<int> p3 = std::make_shared<int>(10);
```

**`拷贝构造、移动构造`**：
```c++
//调用拷贝构造函数
std::shared_ptr<int> p4(p3);
//或
std::shared_ptr<int> p4 = p3;

//调用移动构造函数
std::shared_ptr<int> p5(std::move(p3)); 
//或 
std::shared_ptr<int> p5 = std::move(p3);
```

#### 2.2 销毁

使用智能指针管理对象引用时不需要手动管理内存（delete、delete[]），智能指针会自动释放内存，避免内存泄漏和悬空指针问题。



**`自定义内存释放规则：`**

在初始化 `shared_ptr` 智能指针时，还可以自定义所指堆内存的释放规则，这样当堆内存的引用计数为 `0` 时，会优先调用我们自定义的释放规则。

使用 `C++11` 标准中提供的 `default_delete<T>` 模板类：
```c++
//指定 default_delete 作为释放规则
std::shared_ptr<int> p6(new int[10], std::default_delete<int[]>());
```

自定义释放规则：
```c++
#include <iostream>
#include <memory>

using namespace std;

//自定义释放规则
void deleteInt(int *p) {
    cout<<"delete int array"<<endl;
    delete[] p;
}

int main(int argc, char const *argv[])
{
    shared_ptr<int> ptr1(new int[10], deleteInt);
    cout<<*ptr1<<endl;
    return 0;
}

// 输出
0
delete int array

//------------------------lambda-----------------------
std::shared_ptr<int> p7(new int[10], [](int* p) {delete[]p; });
```

#### 2.3 常见函数

| 函数 | 说明 |
| --- | --- |
| operator=() | 重载赋值号，使得同一类型的 shared_ptr 智能指针可以相互赋值。 |
| operator*() | 重载 * 号，获取当前 shared_ptr 智能指针对象指向的数据。 |
| operator->() | 重载 -> 号，当智能指针指向的数据类型为自定义的结构体时，通过 -> 运算符可以获取其内部的指定成员。 |
| swap() | 交换 2 个相同类型 shared_ptr 智能指针的内容。 |
| reset() | 当函数没有实参时，该函数会使当前 shared_ptr 所指堆内存的引用计数减 1，同时将当前对象重置为一个空指针；当为函数传递一个新申请的堆内存时，则调用该函数的 shared_ptr 对象会获得该存储空间的所有权，并且引用计数的初始值为 1。 |
| get() | 获得 shared_ptr 对象内部包含的普通指针。 |
| use_count() | 返回当前有多少个 shared_ptr 实例共享管理同一个对象的引用计数。 |
| unique() | 判断当前 shared_ptr 对象指向的堆内存，是否不再有其它 shared_ptr 对象再指向它。 |
| operator bool() | 判断当前 shared_ptr 对象是否为空智能指针，如果是空指针，返回 false；反之，返回 true。 |

> 除此之外，`C++11` 标准还支持同一类型的 `shared_ptr` 对象，或者 `shared_ptr` 和 `nullptr` 之间，进行 ==，!=，<，<=，>，>= 运算。

#### 2.4 注意事项

[智能指针shared_ptr的用法](https://bbs.huaweicloud.com/blogs/276199)

- **一、不要使用单个裸指针初始化多个 `shared_ptr`**

**`代码示例：`**

```c++
#include <iostream>
#include <memory>

using namespace std;

class object
{
public:
    object(int val);
    ~object();
    int *age;
};

object::object(int val)
{
    age = new int(val);
}

object::~object()
{
    cout<<"析构"<<endl;
    delete age;
    age = nullptr;
}

void doSomething()
{
    object *value = new object(10);
    shared_ptr<object> ptr1(value);
    shared_ptr<object> ptr2(value);
    cout<<ptr1.use_count()<<endl;
    cout<<ptr2.use_count()<<endl;
}

int main(int argc, char const *argv[])
{
    doSomething();
    cout<<"end"<<endl;
    return 0;
}
```
输出：
```c++
1
1
析构
析构
shared_main(31331,0x7fffa101d380) malloc: *** error for object 0xb000000000000000: pointer being freed was not allocated
*** set a breakpoint in malloc_error_break to debug
Abort trap: 6
```

这样会导致两个 `shared_ptr` 管理同一个对象，当其中一个被销毁时，其管理的对象会被销毁，而另外一个销毁时，对象会二次销毁，然而实际上，对象已经不在了，最终造成严重后果。

- **二、尽量使用 `make_shared`**

原因在下方。

#### 2.5 shared_from_this

[std::enable_shared_from_this 以及使用注意](https://www.jianshu.com/p/74a8a737691a)

```c++
#include <iostream>
#include <memory>

using namespace std;

struct object : public enable_shared_from_this<object>
{
    object(/* args */)
    {
        cout<<"构造"<<endl;
    }

    ~object()
    {
        cout<<"析构"<<endl;
    }

    shared_ptr<object> getPtr()
    {
        return shared_from_this();
    }
};

int main(int argc, char const *argv[])
{
    shared_ptr<object> ptr1(new object());
    shared_ptr<object> ptr2 = ptr1->getPtr();

    if (ptr1 == ptr2)
    {
        cout<<"true"<<endl;
    }
    else
    {
        cout<<"false"<<endl;
    }
    return 0;
}
```
输出：
```
构造
true
析构
```

**`这部分是猜测：`**
> 看到 `enable_shared_from_this` 模板的源码可以知道，`shared_from_this` 返回的是一个 `weak_ptr`，而它是在 `shared_ptr` 的一个构造里赋值的。所以必须又 `shared_ptr` 指针调用 `shared_from_this` 才有效。

**`注意事项：`**

* **一、不要在`构造函数`中调用 `shared_from_this()`**

按照初始化顺序：

1. 调用 `enable_shared_from_this` 构造函数；
2. 调用子类构造函数；
3. 调用 `shared_ptr` 构造函数；
4. `weak_ptr` 赋值；

所以在构造函数中是无法获取到 `weak_ptr` 的。

* **二、不要在`析构函数`中调用 `shared_from_this()`**

由于在析构函数调用前智能指针已经计数清零了，所以在析构函数中是无法获取到 `weak_ptr` 的。

### 3. unique_ptr

[C++11 unique_ptr智能指针详解](http://c.biancheng.net/view/7909.html)

`unique_ptr` 和 `shared_ptr` 指针最大的不同之处在于，`unique_ptr` 指针指向的堆内存无法同其它 `unique_ptr` 共享，也就是说，每个 `unique_ptr` 指针都独自拥有对其所指堆内存空间的所有权。

#### 3.1 初始化

**`定义`**：
```c++
std::unique_ptr<int> p1();
```

**`初始化`**：
```c++
// 空指针
std::unique_ptr<int> p2(nullptr);
// 正常初始化
std::unique_ptr<int> p3(new int(10));
// 错误初始化方式
std::unique_ptr<int> p3 = new int(10); 
```

**`C++14`** 标准中还提供了 `std::make_shared<T>` 模板函数，其可以用于初始化 `shared_ptr` 智能指针
```c++
std::unique_ptr<int> p3 = std::make_unique<int>(10);
```

**`移动构造`**：由于 `unique_ptr` 指针都独自拥有对其所指堆内存空间的所有权，所以不可以通过拷贝构造函数创建 `unique_ptr` 指针。
```c++
// 错误
// std::unique_ptr<int> p4 = p3;
// 正确
std::unique_ptr<int> p4(std::move(p3));
```

#### 3.2 销毁

`unique_ptr` 使用数据结构（`struct`）或类（`class`）进行销毁。

```c++
#include <iostream>
#include <memory>

using namespace std;

class custom_class_delete
{
public:
    void operator()(int *p) {
        cout<<"delete class operator"<<endl;
        delete p;
    }
};

struct custom_struct_delete
{
    void operator()(int *p) {
        cout<<"delete struct operator"<<endl;
        delete p;
    }
};

int main(int argc, char const *argv[])
{
    unique_ptr<int, custom_class_delete> ptr1(new int(10), custom_class_delete());
    cout<<*ptr1<<endl;
    unique_ptr<int, custom_struct_delete> ptr2(new int(20), custom_struct_delete());
    cout<<*ptr2<<endl;
    return 0;
}
```

输出：

```
10
20
delete struct operator
delete class operator
```

| 成员函数名 | 功 能 |
| --- | --- |
| operator*() | 获取当前 unique_ptr 指针指向的数据。 |
| operator->() | 重载 -> 号，当智能指针指向的数据类型为自定义的结构体时，通过 -> 运算符可以获取其内部的指定成员。 |
| operator =() | 重载了 = 赋值号，从而可以将 nullptr 或者一个右值 unique_ptr 指针直接赋值给当前同类型的 unique_ptr 指针。 |
| operator `[]()` | 重载了 [] 运算符，当 unique_ptr 指针指向一个数组时，可以直接通过 [] 获取指定下标位置处的数据。 |
| get() | 获取当前 unique_ptr 指针内部包含的普通指针。 |
| get_deleter() | 获取当前 unique_ptr 指针释放堆内存空间所用的规则。 |
| operator bool() | unique_ptr 指针可直接作为 if 语句的判断条件，以判断该指针是否为空，如果为空，则为 false；反之为 true。 |
| release() | 释放当前 unique_ptr 指针对所指堆内存的所有权，但该存储空间并不会被销毁。 |
| reset(p) | 其中 p 表示一个普通指针，如果 p 为 nullptr，则当前 unique_ptr 也变成空指针；反之，则该函数会释放当前 unique_ptr 指针指向的堆内存（如果有），然后获取 p 所指堆内存的所有权（p 为 nullptr）。 |
| swap(x) | 交换当前 unique_ptr 指针和同类型的 x 指针。 |

### 4. weak_ptr

[C++11 weak_ptr智能指针](http://c.biancheng.net/view/7918.html)

`weak_ptr` 通常和 `shared_ptr` 搭配使用，单独使用时并无实际用处。通过 `weak_ptr` 可以获取 `shared_ptr` 指针的一些状态，比如指针计数，目标内存是否释放等。

#### 4.1 初始化

**`定义`**：
```c++
std::weak_ptr<int> wp1;
```

**`初始化`**：
```c++
std::shared_ptr<int> sp (new int);
std::weak_ptr<int> wp2 (sp);
```

**`构造初始化、移动初始化`**：
```c++
std::weak_ptr<int> wp3 (wp2);
std::weak_ptr<int> wp4 (std::move(wp2));
```

#### 4.2 销毁

无

#### 4.3 常见函数

| 成员方法 | 功 能 |
| --- | --- |
| operator=() | 重载 = 赋值运算符，是的 weak_ptr 指针可以直接被 weak_ptr 或者 shared_ptr 类型指针赋值。 |
| swap(x) | 其中 x 表示一个同类型的 weak_ptr 类型指针，该函数可以互换 2 个同类型 weak_ptr 指针的内容。 |
| reset() | 将当前 weak_ptr 指针置为空指针。 |
| use_count() | 查看指向和当前 weak_ptr 指针相同的 shared_ptr 指针的数量。 |
| expired() | 判断当前 weak_ptr 指针为否过期（指针为空，或者指向的堆内存已经被释放）。 |
| lock() | 如果当前 weak_ptr 已经过期，则该函数会返回一个空的 shared_ptr 指针；反之，该函数返回一个和当前 weak_ptr 指向相同的 shared_ptr 指针。 |

#### 4.4 使用

```c++
#include <iostream>
#include <memory>
using namespace std;
int main()
{
    std::shared_ptr<int> sp1(new int(10));
    std::shared_ptr<int> sp2(sp1);
    std::weak_ptr<int> wp(sp2);
    //输出和 wp 同指向的 shared_ptr 类型指针的数量
    cout << wp.use_count() << endl;
    //释放 sp2
    sp2.reset();
    cout << wp.use_count() << endl;
    //借助 lock() 函数，返回一个和 wp 同指向的 shared_ptr 类型指针，获取其存储的数据
    cout << *(wp.lock()) << endl;
    return 0;
}
```
输出：
```c++
2
1
10
```

### 5. shared_ptr vs unique_str
区别如下：

1. 所有权：

* `std::unique_ptr` 是独占所有权的智能指针。一个 `std::unique_ptr` 拥有对其指向的对象的唯一所有权，当 `std::unique_ptr` 被销毁时，它负责释放其所拥有的对象。
* `std::shared_ptr` 允许多个 `std::shared_ptr` 实例共享对同一对象的所有权。它使用引用计数来跟踪对象的所有权，当最后一个 `std::shared_ptr` 指向对象时，对象的内存会被释放。

2. 构造和拷贝：

* `std::unique_ptr` 不能被拷贝，但可以被移动。这反映了其独占所有权的特性，因此只能有一个 `std::unique_ptr` 指向一个对象。
* `std::shared_ptr` 是可拷贝的，因为它使用引用计数来管理对象的所有权，可以有多个 `std::shared_ptr` 共享同一个对象。

3. 性能开销：

* 由于 `std::shared_ptr` 使用引用计数，它需要维护一个计数器，这可能会引入一些额外的开销。
* `std::unique_ptr` 通常比 `std::shared_ptr` 更轻量，因为它不需要维护引用计数。

4. 循环引用：

* `std::shared_ptr` 可能会导致循环引用问题，即两个或多个 `std::shared_ptr` 对象相互引用，导致引用计数无法降为零，内存无法释放。
* `std::unique_ptr` 不存在循环引用问题，因为它无法拷贝，因此无法形成环。
