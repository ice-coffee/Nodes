## 笔试
https://leetcode.cn/problems/merge-two-sorted-lists/description/
将两个升序链表合并为一个新的 升序 链表并返回。新链表是通过拼接给定的两个链表的所有节点组成的。 
```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        
    }
};
```

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        ListNode dummy(0);
        ListNode* cur = &dummy;

        while (list1 && list2) {
            if (list1->val <= list2->val) {
                cur->next = list1;
                list1 = list1->next;
            } else {
                cur->next = list2;
                list2 = list2->next;
            }
            cur = cur->next;
        }

        // 拼接剩余部分（其中一个已为空）
        cur->next = list1 ? list1 : list2;

        return dummy.next;
    }
};
```

## 一、基础语法

### 1. 基本数据类型与类型转换（约 2 分钟）

**题目**

1. `char`、`int`、`float`、`double` 分别占多少字节？这些大小是标准固定的吗？
2. `signed` 和 `unsigned` 有什么区别？下面代码输出什么？

```cpp
unsigned int a = 1;
int b = -2;
std::cout << (a > b);
```

3. 为什么跨平台项目常用 `int32_t`、`uint64_t`？
4. 隐式类型转换有哪些风险？`static_cast`、`dynamic_cast`、`const_cast`、`reinterpret_cast` 分别用于什么？

**参考答案要点**

- 常见 64 位平台：`char` 1、`short` 2、`int` 4、`float` 4、`double` 8；`long` 在 Linux 64 位是 8，在 Windows 64 位是 4。
- 标准只规定最小范围和相对大小，不固定具体字节数；`sizeof(char)` 一定为 1。
- `signed` 最高位是符号位；`unsigned` 没有符号位，按模 \(2^n\) 运算。
- 上例输出 `0`（false）：`int` 和 `unsigned int` 比较时，`b` 会先转换成无符号数，`-2` 变成一个很大的正数，所以 `1 > b` 反而为假。这正是有符号/无符号混用最容易踩的坑。
- 固定宽度类型用于协议、序列化、跨平台数据结构，避免不同平台 `int`/`long` 宽度不一致。
- 隐式转换的风险：`double` 转 `int` 截断小数、窄化丢高位、有符号/无符号混用、指针与整数误转。
- `static_cast`：数值转换、有继承关系的上行转换；`dynamic_cast`：多态类型的向下转换，运行时检查；`const_cast`：增删 `const`；`reinterpret_cast`：按位重新解释，最危险，尽量不用。

**加分追问**

- `sizeof(int)` 一定等于 4 吗？（不一定，标准只保证至少 16 位）
- C 风格强制转换 `(int)x` 有什么问题？（语义不明确，可能同时包含 `static_cast`、`const_cast`、`reinterpret_cast`）

### 2. const 的用法（约 2 分钟）

**题目**

1. `const` 修饰变量、函数参数、成员函数分别是什么含义？
2. 下面三种写法有什么区别？

```cpp
const int* p1;
int* const p2;
const int* const p3;
```

3. `const` 成员函数里能修改成员变量吗？有什么例外？

**参考答案要点**

- `const` 变量只读，不能再赋值，通常需要在定义时初始化；`const` 引用参数表示函数不会修改实参，且避免拷贝；`const` 成员函数表示不修改对象状态，可以被 `const` 对象调用。
- `const int* p1`：指向的数据是只读的，`p1` 本身可以重新指向；`int* const p2`：指针本身只读，不能重新指向，但可以通过它改数据；`const int* const p3`：两者都只读。
- 记忆方法：`const` 在 `*` 左边修饰指向的数据，在 `*` 右边修饰指针本身。
- `const` 成员函数不能修改非 `mutable` 成员，也不能调用非 `const` 成员函数；`mutable` 成员可以在 `const` 函数中修改（常用于缓存、计数）。
- 同一个成员函数可以同时提供 `const` 和非 `const` 版本，`const` 对象调用 `const` 版本。

**加分追问**

- 为什么函数参数常用 `const T&`？（避免拷贝，同时防止误改）
- `const` 和 `constexpr` 的区别？（`const` 强调只读，`constexpr` 强调编译期可求值）

### 3. 指针与引用（约 2 分钟）

**题目**

1. 指针和引用有什么区别？
2. 什么是野指针？产生原因有哪些？如何避免？
3. `nullptr` 和 `NULL` 有什么区别？
4. `void*` 有什么特点？

**参考答案要点**

- 引用是变量的别名，必须在创建时绑定，不能重新绑定，使用时不需要解引用；指针保存地址，可以为空、可以重新指向、可以做算术运算。
- 野指针是指向不可用内存的指针，常见原因：未初始化、`delete`/`free` 后未置空、越界访问后继续使用。
- 避免方式：定义时初始化、释放后置 `nullptr`、优先使用智能指针、不返回局部变量的地址或引用。
- `NULL` 通常是被定义为 `0` 的宏，重载时可能被当成 `int`；`nullptr` 是 `std::nullptr_t` 类型，类型安全，推荐使用。
- `void*` 可以接收任意类型的指针，但转回具体类型必须显式转换，且不能直接做指针算术。
- 指针大小与指向类型无关：32 位通常 4 字节，64 位通常 8 字节。

**加分追问**

- `p + 1` 移动了多少字节？（`sizeof(*p)` 个字节，不是 1 个字节）
- 函数返回引用需要注意什么？（不能返回局部变量的引用）

### 4. 常用关键字（约 2 分钟）

**题目**

1. `static` 修饰局部变量、全局变量、成员变量、成员函数分别是什么效果？
2. `inline` 的作用是什么？为什么函数可以定义在头文件里？
3. `explicit` 解决什么问题？
4. `= default` 和 `= delete` 分别用于什么场景？

**参考答案要点**

- `static` 局部变量：只初始化一次，生命周期持续到程序结束；`static` 全局变量/函数：内部链接，只在本编译单元可见；`static` 成员变量：属于类，所有对象共享；`static` 成员函数：没有 `this` 指针，不能访问非静态成员。
- `inline` 建议编译器在调用处展开，减少函数调用开销；更重要的是允许函数在多个编译单元中重复定义（要求定义完全一致），所以适合放在头文件。类体内定义的函数默认是 `inline`。
- `explicit` 修饰单参数构造函数，禁止隐式转换，例如避免 `MyClass obj = 10;` 这种意外构造。
- `= default` 让编译器生成默认实现（如默认构造、拷贝构造）；`= delete` 显式禁用某个函数（如禁止拷贝）。
- `static` 成员变量在 C++17 之前需要在类外定义，C++17 起可以用 `inline static` 在类内定义。

**加分追问**

- `static` 成员函数能访问非静态成员吗？（不能，没有 `this`）
- `inline` 一定能展开吗？（不一定，只是建议，编译器可以拒绝）

## 二、类与对象

### 5. 构造函数与析构函数（约 2 分钟）

**题目**

1. 构造函数和析构函数分别有什么特点？
2. 初始化列表和函数体内赋值有什么区别？哪些成员必须用初始化列表？
3. 成员的初始化顺序由什么决定？
4. 下面代码有什么问题？

```cpp
class T {
    int b_;
    int a_;
public:
    T(int v) : a_(v), b_(a_ + 1) {}
};
```

**参考答案要点**

- 构造函数名与类名相同，没有返回值，可以重载；析构函数名为 `~类名`，没有参数和返回值，不能重载。
- 初始化列表是**直接初始化**成员，函数体内赋值是**先默认构造再赋值**；`const` 成员、引用成员、没有默认构造函数的类成员必须用初始化列表。
- 成员初始化顺序由**声明顺序**决定，与初始化列表的书写顺序无关。
- 上例先初始化 `b_`，此时 `a_` 还未初始化，`b_ = a_ + 1` 读取了未初始化的值，属于未定义行为。
- 构造顺序：基类 → 成员（按声明顺序）→ 派生类构造函数体；析构顺序相反：派生类析构函数体 → 成员（逆序）→ 基类。

**加分追问**

- `A a;` 和 `A a();` 有什么区别？（后者是函数声明，不是对象定义）
- 析构函数什么时候需要手动写？（需要释放裸指针等资源时）

### 6. 拷贝构造、赋值与深浅拷贝（约 2.5 分钟）

**题目**

1. 拷贝构造函数和赋值运算符分别在什么场景调用？
2. 什么是浅拷贝和深拷贝？浅拷贝会带来什么问题？
3. 什么是「三法则」？
4. 下面两行分别调用什么？

```cpp
Test obj2 = obj1;  // ①
obj2 = obj1;       // ②
```

**参考答案要点**

- 拷贝构造用于**用已有对象初始化新对象**；赋值运算符用于**给已经存在的对象重新赋值**。
- 浅拷贝只复制指针的值，两个对象指向同一块内存，析构时会重复释放；深拷贝会重新分配内存并复制内容。
- 类中拥有裸指针资源时，需要自定义析构函数、拷贝构造函数、拷贝赋值运算符，这就是三法则；C++11 加入移动构造和移动赋值后称为五法则。
- ① 调用拷贝构造函数（新对象）；② 调用拷贝赋值运算符（已有对象）。
- 拷贝赋值要处理自赋值（`this == &other`），先释放旧资源再复制新资源，并返回 `*this` 支持连续赋值。
- `std::move` 只是把左值转换成右值引用，移动构造会「接管」源对象的资源，源对象之后处于有效但未指定的状态。

**加分追问**

- 为什么移动构造常标 `noexcept`？（`vector` 扩容时更愿意使用移动而不是拷贝）
- 拷贝构造的参数为什么是 `const Test&`？（避免递归拷贝，且能接受临时对象）

### 7. 继承（约 1.5 分钟）

**题目**

1. `public`、`protected`、`private` 继承分别有什么效果？
2. 派生类的构造和析构顺序是什么？
3. 什么是对象切片（slicing）？
4. 虚继承解决什么问题？

**参考答案要点**

- 公有继承保持基类成员的访问级别；保护继承把基类的公有和保护成员变成保护成员；私有继承把它们变成私有成员。
- 基类构造函数 → 成员对象构造（按声明顺序）→ 派生类构造函数体；析构顺序完全相反。
- 基类的私有成员在派生类中不能直接访问，只能通过基类的公有/保护接口访问。
- 对象切片：把派生类对象按值赋给基类对象时，只复制基类部分，派生类特有的成员和虚函数行为丢失。
- 虚继承用于解决菱形继承中的二义性和数据冗余，例如 `class B : virtual public A`；代价是对象布局和访问更复杂，非必要不用。

**加分追问**

- 构造函数、析构函数、拷贝构造函数会被继承吗？（不会，C++11 可以用 `using Base::Base;` 继承构造函数）
- 基类指针可以指向派生类对象吗？反过来呢？（可以；反过来需要显式向下转换且不安全）

### 8. 多态与虚函数（约 2 分钟）

**题目**

1. C++ 多态成立需要哪三个条件？
2. 虚函数和纯虚函数有什么区别？什么是抽象类？
3. 为什么基类的析构函数通常要声明为 `virtual`？
4. 重载、重写、隐藏分别是什么？
5. `override` 和 `final` 有什么作用？

**参考答案要点**

- 三个条件：有继承关系；基类函数是虚函数且派生类重写；通过基类指针或引用调用。
- 虚函数有实现，派生类可以选择重写；纯虚函数写作 `= 0`，通常不提供实现（也可以提供函数体，但类仍是抽象类）；包含纯虚函数的类是抽象类，不能实例化，派生类实现全部纯虚函数后才能实例化。
- 通过基类指针 `delete` 派生类对象时，如果析构函数不是虚函数，只会调用基类析构，派生类资源泄漏，行为未定义；虚析构保证逐层析构。
- 重载：同一作用域内函数名相同、参数不同；重写：派生类重写基类虚函数，签名相同；隐藏：派生类定义了同名函数，把基类的同名函数全部隐藏。
- `override` 让编译器检查是否真的重写了虚函数，签名不匹配会报错；`final` 禁止继续重写或继承。
- 常见实现是虚函数表（vtable）+ 对象内的虚表指针（vptr），基础面试知道这个结论即可。

**加分追问**

- 构造函数能是虚函数吗？析构函数呢？（构造函数不能；析构函数可以且常需要）
- 静态成员函数能是虚函数吗？（不能，虚函数依赖对象）
- 在构造函数/析构函数中调用虚函数会怎样？（只调用当前类的版本，不会派发到派生类）

## 三、模板、异常与 lambda

### 9. 模板基础（约 2 分钟）

**题目**

1. 函数模板和类模板分别怎么写？
2. 什么是模板特化？
3. 模板和宏有什么区别？
4. 为什么模板的定义通常放在头文件里？

**参考答案要点**

- 函数模板：`template <typename T> T max(T a, T b);`；类模板：`template <class T> class Stack { ... };`，使用时写 `Stack<int> s;`。
- 特化：为特定类型提供单独实现，例如 `template <> class MyTemplate<int> { ... };`。
- 模板在编译期实例化，是类型安全的，有作用域和类型检查；宏是预处理阶段的文本替换，没有类型检查，容易产生副作用。
- 模板在实例化时需要看到完整定义，所以通常把实现放在头文件；也可以在 cpp 中显式实例化特定类型。
- 模板支持非类型参数，例如 `template <class T, size_t N> class Array;`，`N` 必须是编译期常量。

**加分追问**

- `typename` 和 `class` 在模板参数列表中有什么区别？（基本等价，`typename` 语义更明确）
- 模板是编译时多态还是运行时多态？（编译时多态）

### 10. 异常处理（约 1 分钟）

**题目**

1. `try`、`catch`、`throw` 的基本用法是什么？
2. C++ 没有 `finally`，如何保证资源释放？
3. `noexcept` 是什么含义？如果 `noexcept` 函数抛异常会怎样？
4. 为什么析构函数不应该抛异常？

**参考答案要点**

- `throw` 抛出异常，`try` 保护代码，`catch` 按类型捕获；建议按 `const` 引用捕获，`catch (...)` 放在最后兜底。
- 异常抛出后会进行栈展开，局部对象的析构函数会被调用；把资源封装进类（RAII），让析构自动释放，就是 C++ 替代 `finally` 的方式。
- `noexcept` 表示函数承诺不抛异常；如果仍然抛出，程序会调用 `std::terminate()` 直接终止，`try/catch` 也接不住。
- 析构函数默认是 `noexcept`，抛异常会导致栈展开过程中再次异常，直接终止程序；析构函数里应吞掉或记录异常。
- 不要用异常做正常的流程控制，异常适合处理真正的错误。

**加分追问**

- 自定义异常类怎么写？（继承 `std::exception`，重写 `what()`）
- 异常安全的三个级别是什么？（基本保证：不泄漏、对象仍可用；强保证：失败时回滚；不抛保证：承诺不抛异常）

### 11. lambda 表达式（约 1 分钟）

**题目**

1. lambda 的基本语法是什么？
2. `[=]`、`[&]`、`[x]`、`[&x]` 分别是什么捕获方式？
3. `mutable` 有什么用？
4. 按引用捕获有什么风险？

**参考答案要点**

- 语法：`[capture](params) -> return_type { body }`，返回类型可以省略，由编译器推导。
- `[=]` 按值捕获外部变量，`[&]` 按引用捕获，`[x]` 只按值捕获 `x`，`[&x]` 只按引用捕获 `x`，`[this]` 捕获当前对象指针。
- 按值捕获的变量在 lambda 内部默认是只读的，加 `mutable` 后才能修改副本，但不会影响外部变量。
- lambda 本质是一个匿名的函数对象（闭包）；按引用捕获时，如果 lambda 的生命周期超过被捕获变量，就会访问悬空引用，属于未定义行为。
- lambda 可以传给 `std::sort`、`std::for_each` 等算法，也可以存进 `std::function`。

**加分追问**

- 按值捕获的对象什么时候被复制？（lambda 创建时）
- C++14 的初始化捕获是什么？（`[x = std::move(v)]`，可以把对象移动进闭包）

## 四、STL 与智能指针

### 12. vector 与 string（约 2.5 分钟）

**题目**

1. `vector` 的 `size()` 和 `capacity()` 有什么区别？
2. `reserve()` 和 `resize()` 有什么区别？
3. `push_back()` 和 `emplace_back()` 有什么区别？
4. `operator[]` 和 `at()` 有什么区别？
5. `std::string` 的 `find()` 找不到时返回什么？`c_str()` 返回什么？

**参考答案要点**

- `size` 是当前元素个数，`capacity` 是已分配空间能容纳的元素数；`size == capacity` 再插入可能触发扩容。
- `reserve(n)` 只预分配容量，不创建元素；`resize(n)` 改变元素个数，多出的元素默认构造（标量零初始化）。
- `push_back` 接受一个已有对象，可能产生临时对象；`emplace_back` 把参数直接传给元素构造函数，就地构造，通常更高效。
- `operator[]` 不做边界检查，越界是未定义行为；`at()` 做边界检查，越界抛 `std::out_of_range`。
- `string::find` 找不到返回 `std::string::npos`；`c_str()` 返回以 `\0` 结尾的 `const char*`，用于传给 C 接口。
- `vector` 扩容和 `erase` 会导致迭代器失效；删除元素常用 `erase(remove(...), end())`。
- C 风格字符串必须以 `\0` 结尾；指向字符串字面量的指针应声明为 `const char*`，不能修改；`char[]` 是数组副本，可以修改。

**加分追问**

- 遍历 `vector` 时为什么推荐 `const auto&`？（避免拷贝，且不能意外修改）
- `"hello" + "world"` 为什么编译不过？（两个都是 `const char*`，至少有一个是 `std::string` 才能用 `+`）

### 13. map 与 unordered_map（约 2 分钟）

**题目**

1. `std::map` 和 `std::unordered_map` 的底层结构、复杂度、遍历顺序有什么区别？
2. `operator[]` 和 `find()` 在判断 key 是否存在时有什么区别？
3. `map` 的 `operator[]` 有什么副作用？
4. 标准库的 `map` 是线程安全的吗？

**参考答案要点**

- `map` 通常是红黑树，按 key 有序，查找/插入/删除 `O(log n)`；`unordered_map` 是哈希表，不保证顺序，平均 `O(1)`，最坏 `O(n)`。
- `operator[]` 在 key 不存在时会插入一个默认值，因此不能用来做纯粹的存在性判断；`find()` 只查找，不修改容器。
- `map` 的 `operator[]` 同样会插入默认值，只判断存在性用 `find()` 或 C++20 的 `contains()`。
- 标准容器不是线程安全的：多线程只读通常可以并发，只要有写就必须加锁。
- 需要有序遍历或范围查询用 `map`；只按 key 快速查找用 `unordered_map`。
- 自定义类型作为 key：`map` 需要比较函数（`operator<` 或自定义 comparator），`unordered_map` 需要哈希函数和相等比较。

**加分追问**

- `unordered_map` 的 rehash 会带来什么影响？（迭代器失效，批量插入前可用 `reserve`）
- `multimap` 中怎么取出同一个 key 的所有值？（`equal_range`）

### 14. 智能指针（约 1.5 分钟）

**题目**

1. `unique_ptr`、`shared_ptr`、`weak_ptr` 分别是什么语义？
2. `unique_ptr` 为什么不能拷贝？怎么转移所有权？
3. `shared_ptr` 的引用计数是怎么工作的？
4. `weak_ptr` 解决什么问题？
5. 为什么推荐 `make_unique` / `make_shared`？

**参考答案要点**

- `unique_ptr` 独占所有权，不能拷贝，只能移动；`shared_ptr` 共享所有权，通过引用计数管理生命周期；`weak_ptr` 不增加引用计数，用于观察 `shared_ptr` 管理的对象。
- `unique_ptr` 拷贝会导致两个指针同时拥有同一资源，所以被禁用；用 `std::move` 转移所有权。
- `shared_ptr` 内部维护引用计数，拷贝时计数加一，析构时减一，减到 0 才释放对象。
- `weak_ptr` 用来打破循环引用（例如父子节点互相持有 `shared_ptr`），通过 `lock()` 获取临时 `shared_ptr`，用 `expired()` 判断对象是否已释放。
- `make_unique`（C++14）和 `make_shared`（C++11）更安全、更简洁，`make_shared` 通常还能把对象和控制块分配在一起，减少一次内存分配。
- 不要用一个裸指针初始化多个 `shared_ptr`，否则会出现多个独立的引用计数，导致重复释放。
- 智能指针用于「拥有资源」；只是观察或借用时用裸指针或引用。

**加分追问**

- 循环引用会导致什么？（引用计数永远不归零，内存泄漏）
- `shared_ptr` 是线程安全的吗？（引用计数操作是原子的，但指向对象的读写仍需同步）

### 15. 线程、锁与原子变量（约 2 分钟）

**题目**

1. `std::thread` 的 `join()` 和 `detach()` 有什么区别？
2. 如果 `std::thread` 对象析构时仍然 joinable，会发生什么？
3. `lock_guard` 和 `unique_lock` 有什么区别？
4. 为什么多线程下 `++counter` 不安全？应该怎么改？
5. `volatile` 能替代 `std::atomic` 吗？

**参考答案要点**

- `join()` 阻塞当前线程，等待子线程结束并回收资源；`detach()` 让线程独立运行，之后不能再等待或管理它。
- 析构时仍 joinable 会调用 `std::terminate()`，程序直接终止；创建线程后必须明确 `join` 或 `detach`。
- `lock_guard` 在构造时加锁、析构时解锁，简单但不能手动解锁、不能延迟加锁；`unique_lock` 更灵活，支持手动加锁/解锁、延迟加锁、移动，配合条件变量时必须用它。
- `++counter` 是读—改—写三步，多线程可能互相覆盖；用 `std::atomic<int>` 或 `std::mutex` 保护。
- 不能。`volatile` 只阻止编译器优化该访问，不保证原子性、不建立线程间同步；线程间共享变量应使用 `std::atomic` 或互斥锁。
- 线程函数参数默认按值保存，需要传引用时用 `std::ref`；线程内未捕获的异常会触发 `std::terminate()`。

**加分追问**

- `condition_variable` 的 `wait` 为什么要配合谓词？（防止虚假唤醒）
- 两个锁加锁顺序不一致会怎样？怎么避免？（死锁；固定加锁顺序或用 `std::lock` / `std::scoped_lock`）
