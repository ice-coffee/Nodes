## 简述
`C++` 项目内存分析基本绕不过这两个文件：

* `/proc/<pid>/maps`：告诉你内存段的 **布局**（虚拟空间）
* `/proc/<pid>/smaps`：告诉你内存段的 **账本**（物理占用、共享/私有、swap 情况）

### 参考
[全面分析C++内存泄漏](https://zhuanlan.zhihu.com/p/1904662949391504941)

好的，这三个是进程内存统计中常见的指标，Android `dumpsys meminfo`、Linux `smem`、`/proc/<pid>/smaps` 里都会出现。它们的含义和区别在于**是否包含共享内存**以及**共享内存如何计数**。

---

### RSS/PSS/USS

**`RSS（Resident Set Size）：`**

* **含义**：进程当前占用的物理内存总量（驻留在 RAM 里的页）。
* **特点**：

  * 包括私有内存 + 完全共享的内存。
  * 不区分共享页属于谁，直接全算到每个进程上。
* **缺点**：

  * 对共享内存重复计数，所以如果多个进程共享一个大内存映射（比如动态库），每个进程的 RSS 都会包含它，看上去总内存占用会被高估。

**`PSS（Proportional Set Size）：`**

* **含义**：按比例分摊共享内存的物理占用。
* **计算**：

  * 私有内存 → 全部计入。
  * 共享内存 → 按共享的进程数平分。
* **特点**：

  * 总和等于系统真实物理占用。
  * 更准确反映一个进程“对系统内存的实际贡献”。
* **Android dumpsys meminfo** 里最常用的就是 PSS。

**`USS（Unique Set Size）：`**

* **含义**：进程**独占**的物理内存（不包含任何共享页）。
* **特点**：

  * 代表该进程如果被杀掉，能立即释放的内存量。
  * 对评估“杀掉进程能回收多少内存”非常有用。

**`对比：`**

| 指标  | 是否包含共享内存 | 共享内存计算方式   | 常见用途         |
| --- | -------- | ---------- | ------------ |
| RSS | ✅ 全部包含   | 共享页全算进每个进程 | 快速查看占用（可能高估） |
| PSS | ✅ 包含     | 按进程数量平分共享页 | 精确反映实际占用     |
| USS | ❌ 不包含    | 只算独占页      | 杀进程可回收内存评估   |

**`举例：`**

* 一个 100MB 的共享库被 5 个进程共享。
* 每个进程还有 50MB 的独占内存。

| 指标  | 结果               |
| --- | ---------------- |
| RSS | 150MB（50 + 100）  |
| PSS | 70MB（50 + 100/5） |
| USS | 50MB             |

#### 在 smaps 文件中

* `RSS` = `Rss` 字段（直接查看）
* `PSS` = `Pss` 字段（直接查看，或 `Shared_Clean` + `Shared_Dirty` + `Private_Clean` + `Private_Dirty` 按共享进程数分摊）
* `USS` = `Private_Clean` + `Private_Dirty`（即进程独占的内存）

#### Linux 下的查看方法

* **RSS**：

```bash
ps -o pid,rss,cmd -p <pid>
```

（单位 KB）

* **PSS / USS**：

```bash
smem -p -P <pid>
```

或：

```bash
grep -i pss /proc/<pid>/smaps | awk '{sum+=$2} END {print sum " kB"}'  # PSS
grep -i private /proc/<pid>/smaps | awk '{sum+=$2} END {print sum " kB"}'  # USS
```

## maps 解析

下方示例移除了大部分重复类型内容：
```
00400000-00440000 r-xp 00000000 103:11 393283          /ota/linux-aarch64/demo/engine_demo/output/bin/test_demo
1e1b0000-1e370000 rw-p 00000000 00:00 0                [heap]
ffff8daa0000-ffff8dac0000 rw-p 00000000 00:00 0
ffff90020000-ffff90040000 r--p 00000000 00:00 0        [vvar]
ffff90040000-ffff90050000 r-xp 00000000 00:00 0        [vdso]
ffff90050000-ffff90080000 r-xp 00000000 fe:00 3392     /usr/lib/aarch64-linux-gnu/ld-linux-aarch64.so.1
ffffd9f60000-ffffd9f90000 rw-p 00000000 00:00 0        [stack]
```

### 结构

举例说明：
```
123a0000-12550000 rw-p 00000000 00:00 0     [heap]
```

`/proc/<pid>/maps` 每行结构是：

```
<起始地址>-<结束地址> <权限> <文件偏移> <设备号> <inode> <映射路径或标记>
```

| 字段          | 值          | 含义                                  |
| ----------- | ---------- | ----------------------------------- |
| **起始地址**    | `1e1b0000` | 该内存段的虚拟地址起始位置                       |
| **结束地址**    | `12550000` | 该内存段的虚拟地址结束位置                       |
| **权限**      | `rw-p`     | 可读(`r`)、可写(`w`)、私有(`p`)、不可执行(无 `x`) |
| **文件偏移**    | `00000000` | 关联文件的偏移量（这里是0，表示不是文件映射）             |
| **设备号**     | `00:00`    | 主设备号和次设备号（`00:00` 表示无设备，通常是匿名内存）    |
| **inode**   | `0`        | 0 表示不是文件映射（匿名映射）                    |
| **映射路径/标记** | `[heap]`   | 特殊标记，表示这是该进程的**堆区**，常见内存段见下文                 |

---

#### 大小计算

```
起始地址：0x123a0000
结束地址：0x12550000
大小     = 0x12550000 - 0x123a0000
         = 0x001B0000 (十六进制)
         = 1,769,472 字节
         ≈ 1.69 MB
```

这表示**当前堆区总容量**是 1.69MB（注意是已分配的虚拟地址空间，不一定都实际用到了物理内存）。

---

#### 权限 `rw-p` 含义

* **r**：可读
* **w**：可写
* **-**：不可执行（安全起见，防止堆中数据被当作代码执行）
* **p**：私有映射（Copy-On-Write，进程间不共享）

### 常见内存段

| 内存段类型| 提供的信息 | 可分析的问题| 程序运行过程中的表现 | 异常时的表现  |
| --- | --- | --- | --- | --- |
| **主程序段 (text/data/bss/rodata)** | 程序 ELF 映射：代码段(`r-xp`)、只读数据(`r--p`)、可写数据(`rw-p`) | ELF 是否加载完整、权限是否正确、安全性检查 | 程序启动时映射固定，通常大小稳定 | 如果缺失或权限错配（如 `rwxp`），可能执行失败或存在安全隐患  |
| **堆 `[heap]`**| 堆起始地址、当前大小  | 动态内存分配趋势、是否依赖 `brk` 分配  | 程序运行时会**扩展**（`malloc`）或在边界处**收缩**（很少） | 堆不断增长但不释放 → 内存泄漏；堆过大 → 虚拟地址空间膨胀，触发 OOM|
| **栈 `[stack]`**  | 主线程栈范围（每个线程也有 `[stack:<tid>]`）| 线程数量、栈大小、栈溢出排查 | 栈大小固定（如 8MB），函数递归或深层调用时逐渐占用  | 栈过深会触发 `Segmentation fault (stack overflow)`；异常时可能出现大量 `[stack:<tid>]`（线程泄漏） |
| **共享库段 (.so)**| 程序依赖的库文件、加载位置、代码/数据段映射  | 动态库依赖问题、符号缺失、是否重复加载  | 程序启动时加载，运行过程中通常稳定| 缺少库 → `undefined symbol` / `library not found`；错误加载路径可能导致 crash  |
| **匿名映射段 (rw-p 无路径)**| `mmap` 分配的内存（glibc 大对象分配、内存池、JIT 内存等）  | 大块内存分配分析、内存池/缓存机制、内存泄漏  | 程序运行时**频繁出现/消失**，尤其在分配大对象时| 如果匿名段越来越多且不释放 → 内存泄漏；如果异常大 → 程序可能占用过多虚拟地址空间 |
| **内存映射文件 (mmap 文件)**| 文件映射（DB 文件、缓存、日志等）| mmap 文件是否过大、数据库/缓存问题 | 程序运行时可能随着访问文件增减  | 如果文件映射异常大，可能导致虚拟内存爆炸；访问非法偏移可能导致 SIGBUS|
| **\[vdso]/\[vvar]/\[vsyscall]** | 内核提供的用户态 syscall 加速接口| 系统调用 ABI 支持情况  | 程序运行时一直存在，大小稳定| 一般不会异常；缺失时某些系统调用可能退化为慢路径  |
| **\[anon] + 权限 (如栈保护页)**  | 匿名内存保护页 (`---p`)  | 内存保护边界| 程序运行时用于隔离堆/栈/库段  | 如果缺失，可能增加内存越界风险  |

### malloc 内存分配策略
glibc 的 `malloc`（ptmalloc2）在分配内存时，主要有两种策略：

**`1. brk/heap 扩展：`**

* 小块内存（默认 ≤128KB）
* 直接通过 `brk()` 系统调用扩展 `[heap]` 区域
* 在 `maps` 里表现为：

```
123a0000-12550000 rw-p 00000000 00:00 0 [heap]
```

堆大小随程序分配而变化

**`2. 匿名 mmap 分配：`**

* 大块内存（默认 >128KB）
* 直接调用 `mmap()` 分配一段匿名虚拟内存
* 在 `maps` 里表现为：

```
7f2e53c00000-7f2e53c21000 rw-p 00000000 00:00 0
7f2e54000000-7f2e54021000 rw-p 00000000 00:00 0
```

没有文件路径，权限通常是 `rw-p`

#### 原因

* 小对象：放在 `[heap]`，因为内存分配/释放频繁，使用 `brk` 扩展堆比较高效
* 大对象：用单独 `mmap`，避免堆空间碎片化，而且大块释放时 `munmap` 能直接还给内核

#### 在 `maps/smaps` 中的表现

**maps：**

* `[heap]`：只显示一块 **连续** 的堆
* 匿名 `rw-p`：显示多个 **不连续** 的段，每段通常大小 **>128KB**

**smaps：**

* 匿名 `rw-p` 段会有：

```
Size:     256 kB
Rss:      256 kB
Anonymous:256 kB
Private_Dirty:256 kB
```
* `[heap]` 段：

```
Size:     8192 kB
Rss:      4000 kB
Anonymous:4000 kB
Private_Dirty:4000 kB
```

#### 分析内存异常时的意义

* **误区**：很多人只盯着 `[heap]` 看，发现不大就以为没问题
* **实际**：如果程序频繁 `malloc >128KB`，那么 `[heap]` 可能稳定，但匿名 `rw-p` 段会越堆越多
* **内存泄漏排查要点**：

  * `[heap]` → 追踪小对象泄漏
  * 匿名 `rw-p` → 追踪大对象泄漏
  * 两者加起来才是完整的动态内存使用

#### 总结

* **glibc malloc 策略**：小块 → heap， 大块 → mmap
* **maps/smaps 表现**：
  * `[heap]` 增长代表小块泄漏
  * 匿名 `rw-p` 增多代表大块泄漏
* **排查建议**：
  * 看 **`[heap] + 匿名 mmap` 总量**
  * 不要只盯堆，否则会漏掉大对象泄漏

## smaps 解析
如果说 `maps` 是进程内存的**地图**（只告诉你“哪一块是堆、哪一块是栈、哪一块是库”），那么 **`smaps` 就是“账本”**，告诉你每一块地到底用了多少“砖头”（物理页）。

### 结构

每个内存段开头一行和 `maps` 格式一致，表示这个段的地址范围、权限、文件映射情况：

```
7f2e53c00000-7f2e53c21000 rw-p 00000000 00:00 0 [heap]
```

后面跟着统计信息（单位：kB），示例：

```sh
Size:               132 kB
Rss:                120 kB
Pss:                 60 kB
Shared_Clean:        40 kB
Shared_Dirty:         0 kB
Private_Clean:        8 kB
Private_Dirty:       72 kB
Referenced:         120 kB
Anonymous:           72 kB
AnonHugePages:        0 kB
ShmemPmdMapped:       0 kB
FilePmdMapped:        0 kB
Shared_Hugetlb:       0 kB
Private_Hugetlb:      0 kB
Swap:                 0 kB
KernelPageSize:       4 kB
MMUPageSize:          4 kB
Locked:               0 kB
VmFlags: rd wr mr mw me ac
```

#### 字段详细说明

| 字段| 含义  | 常用来分析的问题 |
| --- | --- | --- |
| **Size**| 该段的虚拟内存大小 | 和 `maps` 的范围一致 |
| **Rss (Resident Set Size)**  | 实际驻留在物理内存中的大小| 程序真实占用的物理内存 |
| **Pss (Proportional Set Size)** | 按共享比例分配的大小| 多进程共享库时更准确地估算进程占用 |
| **Shared\_Clean** | 共享的、未修改的内存（通常是共享库） | 可以被多个进程共享|
| **Shared\_Dirty** | 共享的、已修改的内存| 共享内存写入|
| **Private\_Clean**  | 只被该进程使用、未修改的内存  | 只读数据  |
| **Private\_Dirty**  | 只被该进程使用、已修改的内存  | 写时拷贝、malloc 分配的内存 |
| **Referenced** | 最近被访问的内存  | 活跃度判断 |
| **Anonymous** | 匿名映射内存 | malloc/new 分配的堆、匿名 mmap |
| **AnonHugePages** | 使用了 Transparent Huge Pages (THP) 的匿名页| 性能优化时参考  |
| **Swap** | 被换出到 swap 的大小| swap 使用过多可能导致性能下降 |
| **KernelPageSize/MMUPageSize**  | 页面大小（通常 4KB 或 2MB） | 大页使用情况|
| **Locked** | mlock 锁定的内存  | 不会被换出 |
| **VmFlags** | 内存段的标志（rd=read, wr=write, ex=execute 等） | 权限与映射类型  |

### 示例解读

假设 `[heap]` 段 `smaps` 内容如下：

```
Size:              2048 kB
Rss:               1900 kB
Pss:               1900 kB
Shared_Clean:         0 kB
Shared_Dirty:         0 kB
Private_Clean:        0 kB
Private_Dirty:     1900 kB
Referenced:        1900 kB
Anonymous:         1900 kB
Swap:                 0 kB
```

解读：

* 虚拟堆大小 = 2MB
* 其中 1.9MB 已实际分配并常驻物理内存
* 全部是 **私有脏页**（即 malloc 分配的内存）
* 没有 swap，说明还没被换出

如果随着时间，`Rss` 不断增加而不下降，就可能是 **内存泄漏**。

## 结合 `maps` 和 `smaps` 的用途

* **Heap 分析**
  看 `[heap]` 段的 `Rss` 是否持续增长 → 判断是否有内存泄漏

* **stack 分析**
  看 `[stack:<tid>]` 数量是否过多 → 判断是否线程异常
  
* **匿名 mmap 分析**
  看 `Anonymous` 和 `Private_Dirty` 是否异常大 → 判断是否大量 malloc/mmap

* **共享库分析**
  看 `Shared_Clean` → 确认共享库是否真正共享内存（多个进程间可节省内存）

* **Swap 分析**
  看 `Swap` → 判断是否存在内存换出，大量出现有性能风险

* **大页分析**
  看 `AnonHugePages` → 是否启用了 Transparent Huge Pages (THP)
  
## 内存监控脚本

抓取内存数据：
```sh
#!/usr/bin/env python3
import os
import time
import subprocess
from datetime import datetime

# 配置
PID = 12345                 # 要监控的进程 PID
THRESHOLD_MB = 500          # 内存异常阈值 (单位 MB)
INTERVAL = 5                # 监控间隔 (秒)
OUTPUT_DIR = "./mem_dumps"  # 存放 maps/smaps 的目录

os.makedirs(OUTPUT_DIR, exist_ok=True)

def get_mem_info(pid):
    """读取 /proc/<pid>/status，返回 VmRSS (MB) 和 VmSize (MB)"""
    rss, vmsize = 0, 0
    try:
        with open(f"/proc/{pid}/status") as f:
            for line in f:
                if line.startswith("VmRSS:"):
                    rss = int(line.split()[1]) // 1024
                elif line.startswith("VmSize:"):
                    vmsize = int(line.split()[1]) // 1024
    except FileNotFoundError:
        return None, None  # 进程不存在
    return rss, vmsize

def dump_maps(pid):
    """抓取 maps 和 smaps 保存到文件"""
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    maps_file = os.path.join(OUTPUT_DIR, f"maps_{pid}_{timestamp}.txt")
    smaps_file = os.path.join(OUTPUT_DIR, f"smaps_{pid}_{timestamp}.txt")

    try:
        subprocess.run(["cp", f"/proc/{pid}/maps", maps_file], check=True)
        subprocess.run(["cp", f"/proc/{pid}/smaps", smaps_file], check=True)
        print(f"[+] Dumped maps/smaps to {maps_file}, {smaps_file}")
    except Exception as e:
        print(f"[!] Failed to dump maps/smaps: {e}")

def monitor(pid):
    baseline_rss = None
    while True:
        rss, vmsize = get_mem_info(pid)
        if rss is None:
            print(f"[!] PID {pid} not found, exiting...")
            break

        print(f"[INFO] PID {pid} | RSS={rss} MB | VIRT={vmsize} MB")

        if baseline_rss is None:
            baseline_rss = rss

        # 条件1：超过阈值
        if rss > THRESHOLD_MB:
            print(f"[ALERT] RSS {rss} MB > {THRESHOLD_MB} MB, dumping...")
            dump_maps(pid)

        # 条件2：相对增长过快（比如超过基线的 2 倍）
        elif rss > baseline_rss * 2:
            print(f"[ALERT] RSS {rss} MB is 2x baseline ({baseline_rss} MB), dumping...")
            dump_maps(pid)

        time.sleep(INTERVAL)

if __name__ == "__main__":
    monitor(PID)
```

内存文件分析：
```sh
#!/usr/bin/env python3
import re
from collections import defaultdict

def parse_maps_line(line):
    parts = line.split()
    addr, perms = parts[0], parts[1]
    offset, dev, inode = parts[2:5]
    pathname = parts[5] if len(parts) > 5 else ""
    start, end = [int(x, 16) for x in addr.split('-')]
    return {
        "start": start,
        "end": end,
        "size": end - start,
        "perms": perms,
        "pathname": pathname
    }

def parse_smaps(file):
    regions = []
    current = None
    with open(file) as f:
        for line in f:
            if re.match(r"^[0-9a-f]", line):  # 新的内存段开始
                if current:
                    regions.append(current)
                current = {"info": line.strip(), "stats": {}}
            else:
                if current is not None:
                    m = re.match(r"(\w+):\s+(\d+)", line)
                    if m:
                        key, val = m.groups()
                        current["stats"][key] = int(val)
        if current:
            regions.append(current)
    return regions

def analyze(maps_file, smaps_file):
    # 读取 maps
    with open(maps_file) as f:
        maps = [parse_maps_line(line) for line in f if line.strip()]

    # 读取 smaps
    smaps = parse_smaps(smaps_file)

    report = defaultdict(lambda: {"virt": 0, "rss": 0, "pss": 0, "count": 0})

    for region in smaps:
        info = region["info"]
        stats = region["stats"]
        size = stats.get("Size", 0)
        rss = stats.get("Rss", 0)
        pss = stats.get("Pss", 0)

        if "[heap]" in info:
            key = "Heap"
        elif "[stack" in info:
            key = "Stack"
        elif "[vdso]" in info or "[vvar]" in info:
            key = "Kernel helper"
        elif "/" in info:  # 文件映射
            key = "File-backed"
        else:  # 匿名段
            key = "Anonymous"

        report[key]["virt"] += size
        report[key]["rss"] += rss
        report[key]["pss"] += pss
        report[key]["count"] += 1

    # 打印结果
    print("==== Memory Usage Report ====")
    for k, v in report.items():
        print(f"{k:12s} | Regions: {v['count']:4d} | "
              f"Virt: {v['virt']:8d} kB | RSS: {v['rss']:8d} kB | PSS: {v['pss']:8d} kB")

    print("\nTip:")
    print("- Heap 持续增大 → 可能内存泄漏")
    print("- Anonymous 匿名段过多/过大 → 大块 mmap 分配或泄漏")
    print("- Stack 段过多 → 线程泄漏")
    print("- File-backed 段过大 → 数据库/缓存 mmap 异常")

if __name__ == "__main__":
    analyze("maps.txt", "smaps.txt")
```
