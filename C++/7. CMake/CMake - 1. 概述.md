## 概述
`CMakeLists.txt` 文件是用于配置 `CMake` 构建系统的文件，而 `CMake` 是一个构建工具，用于管理项目的构建过程。`CMake` 读取项目的 `CMakeLists.txt` 文件，并根据其中的指令和参数生成适用于特定构建系统的构建文件（如 makefile、Ninja build 文件、Visual Studio 项目文件等）。

`CMakeLists.txt` 的语法比较简单且不区分大小写的，推荐使用小写便于查看。

### 静态库和动态库
**`静态库`**：
静态库是一组编译好的二进制目标文件的集合，这些目标文件通常是源代码编译后生成的 .o 文件。静态库在编译链接过程中会被整合到可执行程序中，因此它们成为可执行文件的一部分。静态库在链接时会被复制到可执行文件中，因此可执行文件在运行时不需要依赖外部的库文件。

**特点**：

* 编译时链接：静态库在编译链接过程中被整合到可执行程序中。
* 不需要动态链接器：静态库的函数在编译时被链接到可执行文件中，因此在运行时不需要动态链接器（如 Linux 下的 ld.so）。
* 可移植性：静态库的可执行文件可以在没有库文件的系统上运行，因为所有的依赖都被链接到可执行文件中。

**后缀**：

* Windows：通常使用 `.lib` 作为静态库的后缀名。
* Linux/Unix：通常使用 `.a`（Archive）作为静态库的后缀名。

**`动态库`**：
动态库是一组二进制目标文件的集合，它们在运行时被加载到内存中，并可以被多个可执行程序共享。动态库在编译链接时并不会被整合到可执行程序中，而是在运行时由动态链接器加载到内存中，因此可执行程序在运行时依赖于动态库。

**特点**：

* 运行时链接：动态库在运行时由动态链接器加载到内存中。
* 可共享：多个可执行程序可以共享同一个动态库，节省内存空间。
* 更新方便：更新动态库可以影响所有依赖它的程序，而不需要重新编译可执行文件。

**后缀**：

* Windows：通常使用 `.dll`（Dynamic Link Library）作为动态库的后缀名。
* Linux/Unix：通常使用 `.so`（Shared Object）作为动态库的后缀名。

**`选择`**：

* **使用静态库**：如果希望程序在不同的系统上运行时不受外部库文件的影响，或者希望确保程序的稳定性和一致性，可以选择使用静态库。
* **使用动态库**：如果希望减少可执行文件的大小，或者希望能够方便地更新和共享库文件，可以选择使用动态库。

> `Android` 原生项目中动态库生成位置：`build/intermediates/cxx/Release/***/obj/`

### target
`CMake` 中 `target` 可以是通过 `add_executable`、`add_library`、`add_custuom_target` 定义的可执行文件、静态/动态库、测试程序。
