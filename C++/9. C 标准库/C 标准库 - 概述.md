# C 标准库概述

## 一句话定义
C 标准库是由 ISO C 标准规定、随符合标准的 C 实现提供的一组头文件、函数、宏和类型。

## 核心理解
- **是什么**：C 语言规范配套的公共程序库接口，例如输入输出、字符串处理、内存分配、数学运算和时间处理。
- **为什么需要它**：为不同平台提供统一的基础能力，避免每个程序重复实现常用操作或直接依赖操作系统细节。
- **它解决了什么问题**：同一份 C 源码可以面向标准接口编写，再由不同平台上的实现完成实际工作。

## 详细解释

### 标准、接口与实现

ISO C 标准规定函数名称、参数、返回值和行为，但通常不规定其内部实现。常见层次如下：

| 层次 | 作用 | 常见例子 |
| --- | --- | --- |
| C 标准 | 规定语言和标准库接口 | C99、C11、C17、C23 |
| C 标准库实现 | 实现标准要求，并常附带平台扩展 | glibc、musl、Microsoft UCRT、newlib |
| 编译器 | 编译 C 源代码 | GCC、Clang、MSVC |

`libc` 是 C 标准库实现的通称，不是某一个固定库的专有名称；`glibc` 是 GNU/Linux 上常见的一种实现。具体实现还可能提供标准范围之外的平台扩展。

### 主要组成

| 类别 | 代表头文件与能力 |
| --- | --- |
| 输入输出 | `<stdio.h>`：文件、标准输入输出、格式化 I/O |
| 通用工具 | `<stdlib.h>`：内存分配、数值转换、排序、程序终止 |
| 字符串与内存块 | `<string.h>`：复制、比较、查找、填充 |
| 字符处理 | `<ctype.h>`：字符分类和大小写转换 |
| 数学 | `<math.h>`：常见数学函数 |
| 时间 | `<time.h>`：日历时间与处理器时间 |
| 错误与诊断 | `<errno.h>`、`<assert.h>` |
| 类型与限制 | `<stdint.h>`、`<stddef.h>`、`<limits.h>`、`<float.h>` |
| 信号 | `<signal.h>`：标准信号处理接口 |
| 本地化 | `<locale.h>`：区域设置 |
| 并发与原子操作 | C11 的 `<threads.h>`、`<stdatomic.h>` |

不同版本的 C 标准新增或调整过部分头文件和接口，使用前需要确认编译模式与实现支持程度。

### 宿主实现与独立实现

C 标准区分两类实现：

- **宿主实现（hosted implementation）**：面向具有操作系统环境的普通程序，应提供完整的标准库。
- **独立实现（freestanding implementation）**：常见于内核、引导程序和嵌入式系统，只要求提供标准规定的有限设施。

因此，并非每个符合 C 标准的环境都必须支持文件 I/O、完整堆内存或所有宿主库功能。

## 关键要点
- ISO C 标准规定接口和行为，glibc、musl 等是具体实现。
- C 标准库以头文件暴露函数、宏和类型，但部分能力还需要链接库代码。
- C 标准库通常不负责自动管理资源，内存、文件等资源需要程序显式释放。
- 可用接口取决于 C 标准版本、宿主或独立环境以及具体实现的支持程度。

## 例子与边界

**正例：**

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *file = fopen("data.txt", "r");
    if (file == NULL) {
        perror("fopen");
        return EXIT_FAILURE;
    }

    fclose(file);
    return EXIT_SUCCESS;
}
```

代码使用标准文件接口，并检查资源获取是否成功，最后显式关闭文件。

**边界情况：**

嵌入式或内核环境可能采用独立实现，不提供完整的 `<stdio.h>`、文件系统或动态内存能力；某些 C11 可选能力（如 `<threads.h>`）也可能未被具体实现支持。

## 关系与连接
- **前置知识**：头文件、声明、指针、数组、编译与链接。
- **关联概念**：libc、系统调用、ABI、C 运行时、[[POSIX - 概述]]。
- **容易混淆**：C 标准库规范、具体 libc 实现和实现提供的平台扩展不是同一范围。
- **上位/下位知识**：上位是 C 语言实现；下位包括输入输出、内存、字符串、数学等模块。

## 常见误区
- 把 glibc 等同于 C 标准库规范；glibc 是实现，并且提供了超出 ISO C 的大量扩展。
- 认为头文件里的所有名称都属于同一标准；实现和功能测试宏可能暴露额外接口。
- 忽略资源所有权和缓冲区边界；C 标准库不会像 C++ RAII 类型那样自动清理大多数资源。

## 应用场景
- **适合用在**：跨平台的基础输入输出、字符串处理、内存管理、数学计算、时间处理和通用算法。
- **不适合用在**：标准未规定的操作系统专属能力，这些通常需要相应的平台接口或跨平台第三方库。
