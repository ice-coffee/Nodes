### 定义
定义对象间一对多的依赖关系，使得每当一个对象改变状态，则所有依赖于它的对象都会得到通知并被自动更新。

### 通用类图

```
// 被观察者抽象类
public abstract class Subject {
    private Vector<Observer> obsVector = new Vector<>();

    public void addObserver(Observer o) {
        this.obsVector.add(o);
    }

    public void removeObserver(Observer o) {
        this.obsVector.remove(o);
    }

    public void notifyObservers() {
        for (Observer o : obsVector) {
            o.update();
        }
    }
}

//观察者抽象类
public interface Observer {
    public void update();
}

//具体被观察者
public class ConcreteSubject extends Subject {

    public void doSomething() {
        super.notifyObservers();
    }
}

//具体观察者
public class ConcreteObserver implements Observer {

    @Override
    public void update() {
        System.out.println("接收到消息,并进行处理!");
    }
}

public static void main(String[] args) {
    ConcreteObserver observer = new ConcreteObserver();
    ConcreteSubject subject = new ConcreteSubject();
    subject.addObserver(observer);
    subject.doSomething();
}
```

### 优缺点

优点：

- 观察者和被观察者之间是抽象耦合；
- 可以实现触发链。

缺点：

观察者模式需要考虑一下开发效率和运行效率问题，一个被观察者，多个观察者，开发和调试就会比较复杂，而且在 `java` 中消息的通知默认是顺序执行，一个观察者卡壳，会影响整体的执行效率。在这种情况下一般考虑采用异步方式。

### 发布订阅模式
发布订阅模式是观察者模式的变种。他们之间的区别我们来简单对比一下。

![image](https://img2018.cnblogs.com/blog/849589/201904/849589-20190424122505055-2083728728.png)

可以看到，观察者模式主要有两个角色：观察者和被观察者。而发布订阅模式有三个角色：订阅者、发布者和调度中心。因为调度中心的存在，订阅者和发布者之间是松耦合的，就像维基百科中的描述他们无需了解彼此是否存在。

### EventBus 中的观察者模式
`EventBus` 中用到的就是上文中观察者模式的变种 - 发布订阅者模式。
