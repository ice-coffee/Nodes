### ANR 异常
什么是 ANR？
`Application not response`。`ANR` 是系统通过与之交互的组件以及用户交互进行超时监控，以判断应用进程是否存在卡死或相应过慢的问题。

系统是如何设计 ANR 的？
以广播举例，广播仅有序广播设置了超时机制。系统发送有序广播时会更新发送时间戳，以此时间计算并设置超时时间（时间优化对齐），最后将该广播发送给接收者，接收到客户端的完成通知之后再发送下一个，整个过程循环执行。如果发送的广播没有及时通知系统，则会在系统服务侧触发超时，判定应用进程相应超时。

发生 ANR 时系统都会获取哪些信息以及工作流程？
搜集本次 `ANR` 相关信息并存储到如下文档中：
- `data/anr/trace`：
- `data/system/dropbox`：Android Dropbox 是 Android 在 Froyo(API level 8) 引入的用来持续化存储系统数据的机制。主要用于记录 Android 运行过程中, 内核, 系统进程, 用户进程等出现严重问题时的 log, 可以认为这是一个可持续存储的系统级别的 logcat。

`SystemServer` 获取系统各个进程CPU使用情况，并发送 `SIGNALQUITE` 给各个应用进程获取相关信息、Java线程状态和堆栈等信息，并将输入写入文件。

如何判定 ANR

- 主线程 `watchdog` 机制：定期向主线程发送探测消息并设置超时监测，如在规定的时间内没有收到发送的探测消息状态更新，则判定 ANR。
- 监听 `SIGNALQUIT` 信号。

导致 ANR 的原因有哪些？

- 主线程耗时
- 主线程阻塞
- 复杂动画导致系统进程负载过重
- 频繁IO

`ANR` 异常就是指应用无响应。

常见产生 `ANR` 异常的原因：

- UI 线程执行耗时操作
- UI 线程阻塞
- 复杂动画

`Android` 卡顿、ANR 基本都和主线程相关，原因如上。而分析卡顿和ANR大多也是通过监控主线程 `Handler` 实现的，例如 `BlockCanary`。
