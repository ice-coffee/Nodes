### 数据结构
数据结构的作用是定义数据的特性或者说行为方式。数据结构的行为方式大致又可以分为存储和使用两种。

* **存储**：数组、链表
* **使用**：是否线程安全、是否支持高并发

#### 常用数据结构及实现
* `List`（列表）
    * `ArrayList`：数组
    * `LinkedList`：链表
    * `Vector`：数组
    * `CopyOrWriteArrayList`：？
* `Set`（集）
    * `HashSet`：无序的 `LinkedHashMap`
    * `TreeSet`：`TreeMap`
* `Map`（散列表）
    * `HashTable`：数组 + 单链表
    * `HashMap`：数组 + 单链表 + 红黑树
    * `ConcurrentHashMap`：数组 + 单链表 + 红黑树
    * `LinkedHashMap`：`HashMap` + 双链表 + 有序 
    * `TreeMap`：二叉树
* `Queue`（队列）
    * `LinedList`：它也实现了 `Queue` 接口
* `Stack`（栈）：
    * `Stack`：Vector

`Queue` 和 `List` 的区别在于，`Queue` 维持了一个先进先出的数据结构，仅支持队尾插入输入，对首获取元素。

#### 数组
数组（Array）是一种`线性表`数据结构。它用一组`连续`的内存空间，来存储一组具有`相同类型`的数据。

优点：

- 下标随机访问速度快。
- 对于排好序的数据通过二分法查找速度快。

缺点：

- 插入、删除效率低。
- 可能浪费内存
- 无法扩容。

问答：

- 下标从零开始的原因。 
- 支持下标随机访问的原理。
- 数组插入操作优化。
- 数组删除操作优化。

#### 链表
链表也是一种 `线性表` 数据结构。但是它并 `不是一块连续的内存空间`，而是通过 `指针` 将一组零散的内存块儿串联起来。`指针` 是一个对象，指向下一个链表单元。

优点：

- 插入删除效率高。
- 内存利用率高，不会浪费内存。
- 大小不固定，拓展灵活。

缺点：

- 链表随机访问第k个元素，需要从第一个元素开始遍历，查找效率低。
- 因为指针的存在会消耗更多的内存。

`链表 VS 数组`

- 数据量较少，频繁做按下标查找运算，使用数组。
- 数据量无法估计，频繁做插入删除运算，使用链表。

#### 栈
抽象数据结构，具有后进先出，先进后出的特点。数组或链表皆可实现栈功能。

栈应用：

- ActivityTask。
- 系统中栈用于存储函数参数和局部变量。
- 表达式计算（比如：`34+13*9+44-12/3`）。
- 括号匹配（比如：`{}{[()]()}`）。
- 浏览器前进后退。

#### 队列
抽象数据结构，具有先进先出，后进后出的特点。数组或链表皆可实现队列功能。

队列应用：

- 阻塞队列。
- 并发队列。
- 线程池资源枯竭时通过队列实现请求排队。

#### 散列表
散列表用的是数组支持按下标随机访问数据的特性，所以散列表其实是数组的一种扩展，由数组演化而来。

散列函数（哈希函数）：能够将任意长度的输入值转变成固定长度的值输出，该值成为散列值，输出值通常为字母和数字的组合。

散列函数（哈希函数）特点：

- 接受长度非常长的输入值。函数实现的方式不同阈值也不同。
- 产生固定长度的输出值。
- 不可逆性。
- 只要输入值不变，输出值也应不变。
- 计算时间不应过长。
- 即使修改了输入值的一个比特位，也会使得输出值发生巨大变化。
- 哈希函数产生的映射关系应当保持均匀。
- 减小散列冲突。

散列冲突：由于散列函数输入值的可选区间大于输出值的区间，所以必然会有两个不同的输入值得到的输出值一致。

散列冲突解决方案：

- 开放寻址法：如果出现散列冲突，就重新探测一个空闲位置，将其插入。
- 链表法：当插入的时候，我们需要通过散列函数计算出对应的散列槽位，将其插入到对应的链表中即可。
