### TCP
`TCP` 是整个传输层协议的一种，`TCP` 基于流，定义了一种面向连接的、可靠的、有序的传输方式。

### TCP 包头

![image](https://static001.geekbang.org/resource/image/64/bf/642947c94d6682a042ad981bfba39fbf.jpg)

* 源端口号，目标端口号
* 序号：顺序问题
* 确认序号：确认发出的包是否收到
* 链接状态：~
* 窗口大小：流量控制

链接状态：

`URG`：紧急标志位，开启时表明此数据包处于紧急状态应该优先处理；
`ACK`：确认标志位，开启时表明确认号有效，否则忽略确认号；
`PSH`：推送标志位，开启时表明应该尽快交付给应用进程，而不必等到缓存区填满才推送，比如 telnet 的场景；
`RST`：复位标志位，开启时表明TCP连接出现连接出现错误，数据包非法拒绝连接；
`SYN`：同步标志位，开启时表明连接建立的标志；
`FIN`：终止标志位，开启时表明释放一个连接；

### TCP 三次握手

![image](https://static001.geekbang.org/resource/image/c0/08/c067fe62f49e8152368c7be9d91adc08.jpg)

1. 第一次握手：客户端发送请求连接数据包，客户端进入 `SYN_SEND` 状态；（数据包：`SYN = 1, seq = x`）。
2. 第二次握手：服务端收到数据包，判断客户端请求连接；然后服务端发送数据包表示收到，服务端进入 `SYN_RCVD` 状态；（数据包：`SYN = 1，seq = y、ack = x + 1`）。
3. 第三次握手：客户端收到数据包，判断服务端已确认收到，再次发送数据包给服务端表示确认，客户端和服务端进入 `ESTABLISHED` 状态，完成三次握手，（数据包：`ACK = 1，seq = x + 1、ack = y + 1`）。

> `SYN`、`ACK` 是 `TCP` 包的标志位，占 `1` 位，仅可赋值 `0 或 1`。
> `seq`、`ack` 是 `TCP` 包的序列号和确认序列号，占 `32` 位，初始序列号随机从 `0 ~ 2^32` 取值，确认序列号为 `ack = seq + 1`。

### TCP 四次挥手

![image](https://static001.geekbang.org/resource/image/bf/13/bf1254f85d527c77cc4088a35ac11d13.jpg)

1. 第一次挥手：客户端发送断开连接数据包，用来关闭客户端到服务端的数据传送，客户端进入 `FIN_WAIT_1` 状态；（数据包：`FIN = 1, seq = p`）。
2. 第二次挥手：服务端收到数据包，判断客户端要断开连接；然后服务端发送数据包表示收到，服务端进入 `CLOSE_WAIT` 状态，客户端收到进入 `FIN_WAIT_2` 状态；（数据包：`ACK = 1，ack = p + 1`）。
3. 第三次挥手：服务端发送数据包，用来关闭服务端到客户端的数据传送，服务端进入 `LAST_ACK` 状态；（数据包：`FIN = 1、ACK = 1, seq = q，ack = p + 1`）。
4. 第四次挥手：客户端收到服务端断开连接数据包，客户端进入 `TIME_WAIT` 状态，接着发送数据包给服务端表示收到，服务端进入 `CLOSED` 状态，完成四次挥手，（数据包：`ACK = 1，ack = q + 1`）。

> `MSL` 是 Maximum Segment Lifetime，报文最大生存时间，它是任何报文在网络上存在的最长时间，超过这个时间报文将被丢弃。

在 `TIME_WAIT` 阶段等待 `2MSL` 是为了确认服务端已经收到 `ACK` 包，如果服务端长时间没有收到 `ACK`，则重发 `FIN`，这时客户端收到也会重发 `ACK`。

当然如果客户端等待超过 `2MSL` 后才服务端重新发送的 `FIN` 包，这时客户端会发送 `RST` 告知服务端。

### QA

#### 都说 TCP 是面向连接的，在计算机看来，怎么样才算一个连接呢？
`TCP` 建立连接的本质就是在客户端和服务端各自维护一定的数据结构（一种状态机），来记录和维护这个 `连接` 的状态。并不是真的会在这两个端之间有一条类似“网络专线”这么一个东西。在IP层，网络情况该不稳定还是不稳定，数据传输走的是什么路径上层是控制不了的，TCP能做的只能是做更多判断，更多重试，更多拥塞控制之类的东西。

`TCP` 较好的比喻是在码头上增加了记录人员，核查人员和督导人员，至于IP层和数据链路层，它没有任何改造。

#### 为什么是三次握手
三次握手确认两件事： 

1. 各自确认对方的存在；
2. 约定初始的数据包的序列号
