#### shell 和 shell脚本
`Shell` 是操作系统的命令行解释器，它允许用户与操作系统进行交互，并执行各种命令和脚本。
`Shell` 脚本是一种用于编写自动化任务和系统管理任务的脚本语言，通过编写一系列的 `Shell` 命令和控制结构，可以实现自动化任务的执行。

#### shell 解释器

* **`sh`**：是标准的 `shell` 解释器，它的二进制文件路径通常是 `/bin/sh`。

* **`bash`**：是 `sh` 的增强版本，在 `sh` 的基础上添加了许多新特性，如命令行编辑、命令历史记录、作业控制等，它的二进制文件路径通常是 `/bin/bash`，是 `Linux` 系统中默认的 `Shell`。

在 `Linux` 系统中 `/bin/sh` 往往是指向 `/bin/bash` 的符号链接。

但在 `Mac OS` 上不是，`/bin/sh` 和 `/bin/bash` 是两个不同的文件，尽管它们的大小只相差100字节左右。

#### 指定 shell 脚本解释器
第一行一般是这样：
```sh
#!/bin/bash
```
`#!` 是一个约定的标记，它告诉系统这个脚本需要什么解释器来执行。

#### 执行 shell 脚本
一般有两种方式执行：

* 作为可执行程序：

```sh
chmod +x test.sh
./test.sh
```

* 作为解释器参数：

```
/bin/bash test.sh

//一般简写为：
bash test.sh
```

示例：
```sh
#!/bin/bash
cd ~
mkdir shell_tut
cd shell_tut

for ((i=0; i<10; i++)); do
    touch test_$i.txt
done
```

#### 系统环境变量和用户环境变量
如要使环境变量永久生效需要将其添加在系统的 `shell` 环境配置文件中。比如常见的 `~/.bash_profile、~/.bashrc` 文件。

首先说明一下 **`登录 Shell 和非登录 Shell`** ：

* **`登录Shell`**：

当用户通过终端登录系统时，系统会创建一个登录`Shell`。这种情况下，`Shell`会读取全局配置文件（如`/etc/profile`）来设置系统范围的环境变量，然后执行用户的个人配置文件（如`~/.bash_profile`）。登录`Shell`会读取全局环境变量文件和用户环境变量文件，因此会加载系统和用户级别的环境变量配置。

* **`非登录Shell`**：

当用户已经登录系统后，在当前终端下新开一个`Shell`会话（例如执行`bash`命令启动新的`Shell`）时，系统会创建一个非登录`Shell`。这种情况下，`Shell`只会读取用户的个人配置文件（如`~/.bashrc`）。非登录`Shell`通常用于在已登录系统的环境下进行交互式操作，如执行命令、编写脚本等。因此，非登录`Shell`只加载用户级别的环境变量配置。

> **`注意`**：在 `~/.bash_profile、~/.bashrc` 等系统配置文件中定义的变量，可以在 `shell` 文件中访问。

**加载时机**：
* `.bash_profile`：用户登录时加载，用户使用非登录 `Shell` 登录系统时不加载。
* `.bashrc`：每次启动 `Bash Shell` 时加载，无论是登录还是非登录 `Shell`。
